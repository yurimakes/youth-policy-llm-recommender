# 제출용 데모 UI 구현 범위

- 결정일: 2026-10-07
- 브랜치: `feature/intake-api`
- 배경: 팀원은 2–3개 화면만 만들 예정이며 아직 시작하지 않았고, 사용자가 이번 작업에서 대신 구현해도 된다고 지시했다.

## 결정

제출용 데모에 시작·질문·결과의 세 화면을 추가한다. 상세 질문은 질문 화면을 재사용하고 결과 안에서 공식 근거와 다음 행동을 보여준다. 세로 카드, 명확한 선택 표시, 큰 다음 버튼, 여백을 중심으로 구성하며 기존 지원장바구니 로고를 사용한다.

HTML/CSS/JavaScript를 기존 FastAPI의 `/demo`에서 제공한다. API와 같은 origin을 사용해 별도 빌드·개발 서버 없이 실행한다. React/TypeScript 방향은 후속 구현으로 유지한다. 판정·질문·후보는 기존 서버 계약을 사용하고 화면에서 자격을 추정하지 않는다.

사용자 진행은 메모리만 사용한다. 모름·건너뛰기, 답변 수정, 상세 선택·거절·중단·복귀, 오류 시 이전 답변 유지와 중복 요청 방지를 연결한다. 로그인·영구 저장·외부 AI·실제 문서 생성·자동 연락은 추가하지 않는다.

## 확인과 병합

순수 Python 계약과 JavaScript 클라이언트 검증은 실행했다. 실제 FastAPI 화면 제공·Windows 전체 회귀·브라우저 조작은 확인 전이므로 PR #3에 새 범위를 기록하고 draft로 되돌린다. 해당 확인이 끝나면 하나의 API·데모 작업세트로 main 병합을 진행한다. 원본 `v0.1-mvp` 태그는 그대로 유지한다.
